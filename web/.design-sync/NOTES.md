# design-sync notes — s2m-ui

## Known render warns

- `Modal` → `[RENDER_THIN]` (`collapsed: true`, `maxHeight: 0`) is expected and benign: `Modal` renders a fixed-position backdrop (`.s2m-modal-backdrop{position:fixed;inset:0}`), which always measures 0px in the render-check's height probe even though content renders correctly. Confirmed visually via `_screenshots/general__Modal.png` and the graded review sheet — full wizard step-1 composition renders complete and styled. `cfg.overrides.Modal = {"cardMode": "single", "viewport": "700x560"}` gives it a fixed frame in the DS pane so it displays properly there regardless of the measured-height warning.

## Repo-specific quirks

- **Review-capture background is white, not the studio's dark `--bg`.** Components with no background of their own by design (`Dropzone`, parts of `ParamSlider`'s knob, `SidePanelSection`'s title text) look low-contrast in `_screenshots/review/*.png` purely because that harness page doesn't set the dark body background the real app always does. This is NOT a token-application failure — the CSS custom properties resolve correctly (verified: border/text colors match the real brand palette, just against white). The main `_screenshots/<group>__<Name>.png` render-check screenshots (and the actual uploaded `<Name>.html` cards) DO render on dark background correctly — only the isolated per-cell grading view is affected. Don't chase this as a bug on future re-syncs; it's cosmetic to the grading step only.
- **`RegistrationSummary` has no visual variant** — its `title` prop accepts any string, but the box is always styled `--success` green (`.s2m-reg` has one hardcoded look). An early preview draft passed a warning-toned custom title ("⚠ RMSE 높음") expecting it to read as a warning; it rendered as a green box with warning text (visually misleading) and also tripped a `[RENDER_ERRORS]` catch during validation. Fixed by dropping the invented custom-title variant — the real app (`ReportPage.tsx`) only ever uses the default title anyway. If a warning/error visual state is ever wanted for registration results, it needs a real `tone` prop added to the component, not just a different title string.

## Re-sync risks (what to watch on the next sync)

- This sync authored previews for all 19 components that were still on the floor card (only `AppShell`/`Button`/`ProjectCard`/`NewProjectCard` were authored before). All prop compositions were sourced from real usage in `web/app/pages/*.tsx` (`DashboardPage`, `WizardPage`, `PipelinePage`, `ReportPage`) — **except** `ParamSlider` and `Timeline`, which are exported from `src/index.ts` but not currently consumed by any page (likely intended for a future param panel / trajectory playback that didn't make it into the current app). Their previews were composed from the component source + the original `design/mockups/pipeline-processing.html` and `report-viewer.html` mockups instead of live usage. If/when the real app starts using them, re-check the authored previews against the real call sites and update if the actual prop usage differs from what was guessed here.
- The project (`5aac68bd-4b83-4df5-939e-ed8929140ab6`) had no `_ds_sync.json` anchor at the start of this sync despite having a pinned `projectId` in config — it previously held a manually-uploaded `design_handoff_scan_to_map_studio/` mockup-screenshot handoff (not design-sync output) rather than a completed prior sync. This run replaced that with the real structured component library (full first-sync scope, since there was no anchor to diff against) and deleted the old handoff files with the user's explicit sign-off. Going forward this project has a real anchor, so future re-syncs will be properly incremental.
- 23 components, 22 KB bundle — small enough that render-check always runs full (no sampling), so `--render-sample` tuning is not a concern here for the foreseeable future.
